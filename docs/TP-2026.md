# Linux security practical: corrected instructor reference

Prepared from the 2025 `block1.pdf`, with the original page references below. This is the full practical reference. Teaching order: session 1 uses sections **1, 2, 4, 5**; session 2 uses **3, 7, 8**; the subsequent session uses **6, 10, 9, 11, 12**. Keep the same containers between sessions. Do not run the entire document as a single afternoon exercise.

## Working convention

Start the environment using the repository README. **TARGET** means the root console opened with `docker compose exec host bash`. **CLIENT** means `docker compose exec attacker bash`. **LAPTOP** means a terminal in the repository on your computer. A block marked `user=alice`, `user=bob` or `user=student` must be run through `docker compose exec --user NAME host bash`, not as root. `expect=N` states the expected exit status for a negative test.

Keep the root Docker console open for recovery. Use these disposable lab passwords only here. Before each practical, predict the allowed and refused operations. Afterward, save evidence and explain the result in your own words.

First compare the server fingerprint displayed in the target console with the fingerprint from the client. Proceed only if they match. The automatic audit also compares the actual public-key bytes across the two consoles.

## 5. Defaults and inherited access (46–53)

Two ideas: umask removes permission bits from a requested mode; ACLs can express an additional role. The formula is `requested_mode & ~umask`, not arithmetic subtraction. `0666` with mask `0027` becomes `0640`; directories requested as `0777` become `0750`.

```bash
# TARGET [umask]
mkdir -p /tmp/umask-demo
cd /tmp/umask-demo
umask 027
touch f
mkdir d
stat -c '%a %n' f d
test "$(stat -c %a f)" = 640
test "$(stat -c %a d)" = 750
umask 077
touch private
test "$(stat -c %a private)" = 600
```

Changing `/etc/login.defs` alone does not alter an already-running shell's umask. Explicitly check `umask` in the session you are testing.

```bash
# TARGET [acl-setup]
groupadd auditors
usermod -aG auditors bob
mkdir -p /srv/project
chgrp admin /srv/project
chmod 2770 /srv/project
setfacl -m g:admin:rwx,g:auditors:rx,m:rwx /srv/project
setfacl -d -m g:admin:rwx,g:auditors:rx,m:rwx /srv/project
getfacl /srv/project | tee /artifacts/project-acl.txt
```

```bash
# TARGET [acl-alice-write] user=alice
```

## 7. SSH source policy and a stateful firewall (60–68)

Two ideas: sshd authorizes the login; nftables filters packets. A `Match Address` block changes settings for matching clients. It does not automatically deny every other address.

```bash

lab_client_ip=$(getent ahostsv4 attacker | awk 'NR==1{print $1}')
test -n "$lab_client_ip"
printf 'AllowUsers alice@%s\n' "$lab_client_ip" > /etc/ssh/sshd_config.d/01-allowlist.conf
sshd -t
kill -HUP 1
python3 -m http.server 8080 --directory /srv/project > /tmp/http8080.log 2>&1 &
echo $! > /run/http8080.pid
sleep 1
```

```bash
# CLIENT [web-before-filter]
curl --fail --max-time 3 http://host:8080/report
```

Before installing the firewall, isolate the SSH source restriction. The next command gives a new disposable client the same **lab-only** key and verified known-host record. Alice is allowed as an account, but the new source address must be refused. It does not copy the key to your laptop or evidence folder.

```bash

  docker compose run --rm -T --no-deps attacker bash -ec '
    mkdir -p /root/.ssh
    tar -xf - -C /root/.ssh
    chmod 600 /root/.ssh/labkey
    ssh -i /root/.ssh/labkey -o BatchMode=yes -o ConnectTimeout=3 alice@host true

```

## 8. Application events and temporary bans (69–83)

Reset only the teaching table, preserve DNS, and count one event per HTTP request. A Python 404 produces both an error description and an access line. Matching both would double the count.

## 10. Chroot and reduced privileges (88–98)

Two ideas: chroot changes a process's filesystem root; a separate UID limits its authority. Chroot alone is not a complete sandbox. Do not set `noexec` on the filesystem containing the binary you need to start.

```bash
# TARGET [chroot-start]
mkdir -p /srv/jail/{bin,www,tmp}
chmod 1777 /srv/jail/tmp
cp "$(command -v busybox)" /srv/jail/bin/busybox
useradd -r -s /usr/sbin/nologin www-chroot
lab_uid=$(id -u www-chroot)
lab_gid=$(id -g www-chroot)
echo 'OK: chrooted web' > /srv/jail/www/index.html
# Keep static served files root-owned: the service only needs to read them.
chroot --userspec="$lab_uid:$lab_gid" /srv/jail /bin/busybox httpd -f -v -p 0.0.0.0:8091 -h /www > /tmp/jail-http.log 2>&1 &
echo $! > /run/jail-http.pid
sleep 1
lab_pid=$(cat /run/jail-http.pid)
ps -o pid,user,args -p "$lab_pid"
awk '/Uid|Gid/' "/proc/$lab_pid/status"
test "$(awk '/^Uid:/{print $2}' "/proc/$lab_pid/status")" = "$lab_uid"
ss -ltnp | grep 8091
```

```bash
# CLIENT [chroot-http]
test "$(curl -fsS --max-time 2 http://host:8091)" = 'OK: chrooted web'
```

```bash
# TARGET [chroot-inside]
lab_uid=$(id -u www-chroot)
lab_gid=$(id -g www-chroot)
chroot --userspec="$lab_uid:$lab_gid" /srv/jail /bin/busybox sh -c '
  /bin/busybox pwd
  /bin/busybox ls -l /
  /bin/busybox id
  test ! -e /etc
  echo jail-marker > /tmp/jail-only
'
test -f /srv/jail/tmp/jail-only
test ! -f /tmp/jail-only
```

```bash
# TARGET [chroot-cleanup]
kill "$(cat /run/jail-http.pid)"
rm /run/jail-http.pid
```

`UID` is a read-only Bash variable. Use `lab_uid` instead. Capturing the direct foreground server's PID avoids accidentally recording the PID of `tee`. The missing `/etc` is an expected result, not a failed setup. BusyBox's shell in the tested Ubuntu package can resolve built-in applets; the explicit calls above make the dependency clear.

## 12. Inventory and investigation with osquery (110–115)

Install the course's pinned version using the helper. It checks the official release's SHA-256 and extracts files as root-owned, instead of restoring archive UID 1000. ARM downloads have a checksum configured; only the Linux x86_64 execution path was tested in this audit.

```bash
# TARGET [osquery-install]
install-osquery-lab
osqueryi '.schema kernel_info'
osqueryi '.schema file'
```

```bash
# TARGET [osquery-inventory]
osqueryi --json 'SELECT lp.address,lp.port,lp.protocol,p.pid,p.name,p.cmdline FROM listening_ports lp LEFT JOIN processes p ON lp.pid=p.pid ORDER BY lp.port;' > /artifacts/listeners.json
osqueryi --json 'SELECT username,uid,gid,directory,shell FROM users ORDER BY uid;' > /artifacts/users.json
osqueryi --json 'SELECT user,tty,host,time FROM logged_in_users;' > /artifacts/sessions.json
osqueryi --json 'SELECT name,version,platform,platform_like FROM os_version;' > /artifacts/os.json
osqueryi --json 'SELECT version,arguments,path,device FROM kernel_info;' > /artifacts/kernel.json
osqueryi --json 'SELECT hardware_model,cpu_brand,physical_memory FROM system_info;' > /artifacts/hardware.json
osqueryi --json 'SELECT total_seconds,days,hours FROM uptime;' > /artifacts/uptime.json
osqueryi --json "SELECT interface,address,mask,broadcast FROM interface_addresses WHERE address NOT LIKE '127.%' AND address != '::1';" > /artifacts/interfaces.json
```

`kernel_info` has no `release` column in version 5.23.1. An empty session list can be correct inside a container. Hardware and uptime can describe the Docker host or VM rather than the student's laptop hardware.

```bash
# TARGET [osquery-investigation]
osqueryi --json 'SELECT path,username,groupname,permissions FROM suid_bin;' > /artifacts/suid.json
osqueryi --json "SELECT path,mode FROM file WHERE path IN ('/usr/bin/sudo','/opt/labtools/shroot');" > /artifacts/selected-files.json
osqueryi --json 'SELECT lp.address,lp.port,p.pid,p.name,p.euid FROM listening_ports lp JOIN processes p ON lp.pid=p.pid WHERE p.euid=0 ORDER BY lp.port;' > /artifacts/root-listeners.json
```
